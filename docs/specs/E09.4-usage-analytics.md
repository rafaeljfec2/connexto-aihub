# SPEC E09.4 — Usage Analytics

**Status:** Approved — increment authorized in delivery request (2026-11-03).
**Scope:** Administrative analytics API over E09.1 admission rows, E09.2 quota state, and E09.3 concurrency capacity. Dashboards deferred.

## Intent

Expose aggregated, content-free queries so operators can inspect admitted Hub request volume, daily trends, provider/model distribution, quota utilization, and current concurrency headroom.

## Data sources

| Metric | Source | Notes |
| --- | --- | --- |
| Admitted requests | `resource_admissions` where `allowed = true` | One row per admission attempt; not provider billing |
| Daily UTC buckets | `resource_admissions.period_start` | Same UTC calendar day as E09 counters |
| Quota utilization | `resource_policies` + `resource_period_counters` | Same semantics as `GET /api/resource-usage` |
| Concurrency capacity | `concurrency_policies` + active `concurrency_leases` | Same semantics as `GET /api/concurrency-usage` |

No second ledger. Rejected admissions (`allowed = false`) are excluded from volume metrics.

## Global total semantics

The **global** admitted count and daily series count distinct successful admissions once. Provider/model breakdowns attribute the same admissions to dimensions; they must not be summed together with the global total.

## Truncated input assumptions

The delivery brief was truncated in the disabled-policy section. Until amended by the project lead:

- **Disabled quota policy:** `remaining_requests = 0`, `utilization_percent = 0`; `admitted_count` still reflects the persisted counter for the period.
- **Enabled policy:** `utilization_percent = min(100, admitted_count / daily_limit × 100)` rounded to two decimals; `remaining_requests = max(0, daily_limit - admitted_count)` when enabled.

## HTTP (admin auth, PostgreSQL mode only)

| Method and path | Purpose |
| --- | --- |
| `GET /api/resource-analytics/admissions` | `total_admitted` and `daily[]` for `[from, to]` UTC days |
| `GET /api/resource-analytics/admissions/distribution` | `by_provider[]` and `by_model[]` with daily UTC buckets |
| `GET /api/resource-analytics/quota-utilization` | Per-policy quota state including `utilization_percent` |
| `GET /api/resource-analytics/concurrency` | Per-policy concurrency active/available snapshot |
| `GET /api/resource-analytics/provider-usage` | Provider-reported token aggregates and execution status counts (E09.5 extension) |
| `GET /api/resource-analytics/provider-usage/distribution` | Provider and provider/model token aggregates (E09.5 extension) |

Query parameters:

- `from`, `to`: required on range endpoints; RFC3339 or `YYYY-MM-DD`; inclusive UTC calendar days; maximum span 366 days; `from` must not be after `to`.
- Optional filters: `provider_id` and `model_id` on admissions and provider-usage range endpoints. A `model_id` requires `provider_id`.
- `period_start`: optional on quota utilization (defaults to current UTC day), RFC3339.

Missing days in series return `admitted_count: 0`.

## Provider usage extension (E09.5)

Provider usage aggregates include token values only from `reported` and `partial` execution records. Each nullable token metric is summed independently from its known values. If no included record reports a value for a metric, the response preserves it as JSON `null`; an explicitly reported zero remains `0`. Gap-filled days with no executions have `execution_count: 0` and `null` token metrics. Distribution responses contain only observed provider or provider/model groups.

Provider-reported cost is persisted separately but is not part of these analytics responses.

## Acceptance criteria

- **AC-1:** Admitted volume uses `resource_admissions` with `allowed = true` only.
- **AC-2:** Daily series are UTC, chronological, gap-filled, and bounded.
- **AC-3:** Global totals are not double-counted across scope/policy dimensions.
- **AC-4:** Quota utilization matches E09.2 counters and adds bounded utilization percent.
- **AC-5:** Concurrency snapshot matches E09.3 usage semantics.
- **AC-6:** Routes require admin credential and return no-store, content-free JSON.
