# E08.4 — Responses Gateway routing integration

**Status:** implemented (local, not committed)

## HTTP rejection mapping

| Rejection / input | HTTP | `error.type` |
| --- | --- | --- |
| Structural `invalid_request` | 400 | `invalid_request` |
| `requirement_unmapped` | 400 | `requirement_unmapped` |
| `provider_not_found` | 404 | `provider_not_found` |
| `model_not_found` | 404 | `model_not_found` |
| `no_eligible_model` (capability / catalog mismatch) | 404 | `no_eligible_model` |
| Explicit provider operational failure (credential, disabled, unbound, responses unsupported, unavailable) | 503 | `provider_unavailable` |
| `provider_model_conflict` | 409 | `provider_model_conflict` |
| `routing_ambiguous` | 409 | `routing_ambiguous` |
| `routing_unavailable` | 503 | `routing_unavailable` |
| Runtime gate after selection (`provider_unavailable`) | 503 | `provider_unavailable` |

## Request preparation (contract §7)

- Explicit top-level `model` in the validated structural input: original body bytes preserved.
- No explicit model and routing selects one: top-level `model` injected via JSON object merge; other fields preserved.

## Integration surface

- `gateway.ResponsesRouting` wired from `cmd/ai-hub/gateway_routes.go` (catalog, provider statuses, stale window).
- `responsesHandler.ServeHTTP` runs the E08 pipeline when `ResponsesRouting` is configured.
- Legacy path (`ResponsesRouting == nil`) retained for focused gateway tests without catalog fixtures.
